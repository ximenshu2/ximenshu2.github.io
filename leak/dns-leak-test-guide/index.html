DNS泄露怎么检测？结果判断与复测步骤

DNS泄露不是“看到陌生DNS”这么简单。判断重点是：查询是否绕过预期连接路径，以及检测结果能否对应到浏览器DoH、系统DNS或VPN提供的解析器。

最后更新：2026-08-17 核对范围：浏览器DNS查询
结论： 先比较连接前后解析器，再核对浏览器是否启用DNS over HTTPS。服务器数量多、地区与出口不同，都不能单独证明泄露；出现本地运营商解析器或连接前解析路径，才是需要继续核对的强信号。

DNS泄露是什么

浏览器访问域名前，通常需要通过DNS把域名解析为网络地址。 如果网页流量按预期经过VPN，但DNS查询仍绕过预期路径， 例如继续发送给本地网络提供的解析器，那么参与这条DNS解析链路的网络或解析服务提供方， 可能观察到相关域名查询。

这里的“DNS泄露”描述的是DNS查询路径没有按照用户预期经过相应的VPN、加密DNS或指定解析服务。 它并不表示普通目标网站因此能够看到你的全部DNS查询， 也不等于DNS解析器能够看到HTTPS页面中的具体路径、正文或你在网页中填写的内容。

DNS over HTTPS 会改变什么

DNS over HTTPS（DoH）会把DNS查询封装在HTTPS连接中发送给指定的DoH解析器。 这会改变谁可以直接观察DNS查询内容，但并不意味着查询一定经过VPN。

如果浏览器自己启用了DoH，它可能优先使用浏览器配置的解析器。 因此，VPN连接正常但检测结果显示第三方公共DNS，并不一定代表泄露； 还要核对浏览器DoH设置是否与当前结果一致。

四步检测

  1. 断开VPN，记录解析器名称、地区、运营方和数量。
  2. 连接VPN，在同一浏览器重新测试，不要同时更改系统DNS。
  3. 检查是否仍出现连接前的本地运营商解析器，并记录浏览器DoH设置。
  4. 换第二个浏览器复测；若结果不同，优先检查浏览器级DNS设置。

常见误区

  • 只看国家名称： 公共解析服务可能使用Anycast，显示位置不一定等于查询真实路径。
  • 把DNS当浏览历史全文： DNS主要处理域名解析，不等于能够看到HTTPS页面的具体路径、正文或表单内容。
  • 看到公共DNS就判定泄露： 浏览器DoH、自定义DNS或系统级加密DNS都可能改变解析器结果。
  • 检测后同时改很多设置： 一次更改浏览器、系统DNS和客户端，无法知道哪个调整有效。
  • 公开完整截图： 截图可能包含真实IP、解析器和设备信息，应先脱敏。

FAQ

DNS服务器越少越安全吗？

不能这样判断。数量取决于解析服务和检测方法，核心是路径是否符合你的配置预期。

使用公共DNS就不会泄露吗？

公共DNS改变了解析服务提供者，但不能自动保证查询一定经过VPN，也不能解决Cookie、账号或浏览器指纹。

启用DoH就一定更安全吗？

DoH可以加密浏览器到DoH解析器之间的DNS查询， 但它改变的是解析路径和可见方，不代表所有网络流量都经过同一隐私保护路径。

修复后应该怎么复测？

回到同一设备、网络和浏览器，重复连接前后对照，只改变一个设置，并记录新结果。
